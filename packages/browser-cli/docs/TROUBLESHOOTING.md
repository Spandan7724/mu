# Troubleshooting

Start with `mu-browser doctor`. It makes no network call and launches no browser, so
it is always safe to run first; it reports your data root and which connection modes
this build can reach.

| Symptom | Cause | Fix |
| --- | --- | --- |
| "the browser is still waiting for the Playwright extension connection to be approved" | You did not click Allow in the browser (or it timed out) when `mu-browser` asked to attach. | Approve the connection in the browser, then retry. |
| Extension connection times out after ~90 seconds and never completes, specifically under WSL | The extension relay was started on the wrong side of the WSL boundary — it must run on the same OS as the browser. | Set `MU_BROWSER_MCP_RUNTIME` / `MU_BROWSER_MCP_CLI` to the Windows-side paths, or switch to `--connection persistent`. See [SETUP.md](./SETUP.md#running-from-wsl). |
| "another Mu browser (pid ..., started ...) already owns \<profile dir\>" | A second `mu-browser --connection persistent` tried to use the same `--browser-profile` name while an earlier session is still holding it. | Close the earlier session, or pass a different `--browser-profile` name. |
| "no installed chrome was found at ..." | None of the standard install locations for the chosen `--browser` had an executable. | Install the browser normally, or set `MU_BROWSER_EXECUTABLE` to its path. Mu never downloads a browser binary. |
| "the browser bridge reports ... but this build of Mu is pinned to ..." | The installed `@playwright/mcp` bridge doesn't match the version this build expects — usually a partial or mismatched install. | Reinstall `@mu-agent/browser`; Mu never upgrades the bridge on its own. |
| `mu-browser -p "..."` refuses a step that would work fine in the interactive app | Headless mode (`-p`) auto-denies any permission check that would otherwise ask — there is no terminal to ask in. | Run it interactively instead, or choose a `--permission-mode` (e.g. `autonomous-submit`) whose rules allow the step outright rather than asking. Do not reach for `--allow-all` to solve this — see [PERMISSIONS.md](./PERMISSIONS.md#--allow-all). |
| The agent stops and asks you to log in, enter a code, or solve a CAPTCHA | This is by design (`browser_takeover`), not a failure: password/passkey/MFA/CAPTCHA fields are a hard stop in every permission mode. | Complete that step in the actual browser, then let the session continue. |
| After a submission, the agent reports the outcome as `unconfirmed` or `unknown` instead of `confirmed`, and won't retry it | The submission's outcome could not be confirmed (network drop, the page navigated away mid-check, an ambiguous response) — `mu-browser` never retries a commitment it cannot confirm, because retrying an unconfirmed submission risks doing it twice. | Check the site directly for whether it actually went through before doing anything else. |
| "the page changed after approval; observe again and re-confirm before committing" | You (or the agent) approved a submission, but the page changed in the time it took to approve it — the target is re-validated immediately before the action, not only when you approved it. | Let the agent re-observe and re-attempt; this is the tool refusing to click on a control that may no longer be what you approved. |
| A document you named with `--document` is refused with "...changed since it was authorized" | The file's bytes on disk differ from what was hashed when you authorized it (edited, or a symlink now points elsewhere). | Re-run with `--document` again to re-authorize the current version. |
| The agent describes a password field as empty, or can't tell you what's currently in a login field | Credential field values are stripped before the agent ever sees the page — this is the boundary described above working as intended, not a bug. | Enter that value yourself in the real browser; it is not something Mu will ever read or fill. |
| `mu-browser` used the wrong model, or the model catalog looks stale | `mu-browser` shares nothing with the coding product's `~/.mu` state — check `~/.mu/browser/config.json` and `~/.mu/browser/models.json`, not the coding product's files. | Set `--model <ref>` explicitly, or edit `~/.mu/browser/config.json`. |
